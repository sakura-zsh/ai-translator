# 2026-10-15 — 接入 Jev（TypeSafe System One 决策模型）

## 背景
用户找到了可用的 Jev 中转站端点（`/v1/systemone`），要求做「Jev 模型相关的适配」，
且明确 **Base URL 不要写死**。定位：三个功能全要 —— 场景自动路由、语种自动检测、
译文质量评分（含低于阈值自动重译）。

## Jev 接口事实（供后续参考）
- 官方原生端点：`POST https://api.typesafe.ai/v1/systemone`
  body = `{state, model, questions}`；`questions` 是 map，每项 `{type, instructions, criteria}`，
  type ∈ `choice` / `score` / `noul`。
- 响应：`{model, answers: {qid: {...}}, usage}`；
  choice 返回 `choice` + `probabilities` + `confidence`，score 返回 `score` + `legend`，noul 返回 `noul`(0–1)。
- 中转站常见变体：`/api/v1/decide`、`/v1/decide`；也可能用 `/chat/completions` 包成 OpenAI 形状。
- 模型名：`jev-latest` 或 `jev-1.13.0`（中转站可能带前缀）。
- 闭源、无权重、不能本地部署。

## 实现
- 新增 `app/core/jev_client.py`：`JevClient` 双协议（native + openai），
  `api_protocol="auto"` 按候选端点探测并缓存（模块级 `_ROUTE_CACHE`，键 = 协议|base_url）；
  请求体两种都发得出去，响应结构两种都解析得了（`_RouteMismatch` 用于可重试的「形状不符」）。
  高层方法 `detect_language` / `route_scene` / `score_quality`，外加 `test_connection` / `list_models`。
- `app/config/schema.py`：新增 `JevConfig`（`base_url` 默认空串 = 不写死），挂到 `AppConfig.jev`；
  `from_dict` 做清洗（阈值钳 0–1、timeout 钳 5–600、未知协议回 auto、空模型名回 jev-latest）。
- `app/ui/main_window.py`：`_jev_client` / `_jev_feature` / `_jev_preprocess` / `_jev_score` /
  `_jev_extra_prompt`；新增 `_run_translation()` 统一「Jev 预处理 → 翻译 → 评分 →（可选）重译一次」，
  文本路径与 OCR 图片路径共用；场景下拉在 Jev 启用时追加「自动判断（Jev）」项。
- `app/ui/settings_dialog.py`：新增「Jev 判断」标签页（Base URL / Key / 模型 / 协议 / 超时 /
  三个功能开关 / 质量阈值 / 重译开关 / 测试连接）。
- `app/core/presets.py`：新增 `AUTO_SCENE_ID` / `AUTO_SCENE_LABEL` 与 `combine_extra_prompt()`。
- 关键原则：**Jev 失败绝不中断翻译**，全部 try/except 后记日志降级。

# 2026-10-15（晚）— 重新打包 Windows exe + 安装包（v0.4.0，含 Jev）

## 结论
- 产物：`packaging/windows/dist-0.4.0/ai-translator/ai-translator.exe`（9.0 MB）
  与 `packaging/windows/installer/ai-translator-setup-0.4.0.exe`（56.5 MB）。
- 版本号来源 `app/__init__.py` = **0.4.0**（pyproject 是动态版本，读这里）。

## 可复现的打包流程（本项目 Windows）
```bash
# 1) PyInstaller —— 关键：distpath 用「全新目录」，workpath 复用 build/ 保留分析缓存
"$PY313/python.exe" -m PyInstaller --noconfirm \
  --distpath "packaging/windows/dist-0.4.0" \
  --workpath "packaging/windows/build" \
  "packaging/windows/ai-translator.spec"

# 2) Inno Setup —— DistDir 是相对 iss 的路径
"$LOCALAPPDATA/Programs/Inno Setup 6/ISCC.exe" \
  "/DAppVersion=0.4.0" "/DDistDir=dist-0.4.0" \
  "packaging/windows/ai-translator.iss"
```

## 踩坑 / 设计决策
- **不要直接用 `build-windows.ps1`**：它 `--noconfirm` 到已存在的 `dist/`，会触发
  沙箱的批量删除保护钩子而失败；且脚本里的 `python` 在工具环境不在 PATH。
  或者它在 PowerShell 管道下 `Tee-Object` 也不稳。手动两步最可靠。
- 已把 `ai-translator.iss` 的源目录**参数化**：新增 `#ifndef DistDir / #define DistDir "dist"`，
  `Source: "{#DistDir}\ai-translator\*"`。以后换输出目录只需 `/DDistDir=xxx`，
  不必再复制出 `ai-translator-rel.iss` 这类一次性副本（该文件属历史遗留，可删）。
- 冒烟测试别用 `taskkill //F`（Git Bash 会传成 `//F` 报「无效参数」），
  用 PowerShell `Stop-Process -Name ai-translator -Force`。

## 验证手段（打包后如何确认改动静默地进了包）
PyInstaller 的构建日志**不列出**纯 Python 模块，只能查冻结归档：
```python
from PyInstaller.archive.readers import CArchiveReader, ZlibArchiveReader
r = CArchiveReader(exe); data = r.extract("PYZ.pyz")   # 写出临时文件
z = ZlibArchiveReader(tmp); mods = sorted(z.toc)       # 1185 个模块
assert "app.core.jev_client" in mods
```
本次确认 `app.core.jev_client`、`app.core.presets` 均在归档内；
再实机启动 exe 存活 8s（无导入崩溃）后清理进程。
