# ai-translator 项目工作日志

## 2026-09-04 Windows 全局热键 + IPC 修复

### 热键不生效的根因
- 原有热键全部是 `QShortcut(..., self)`（窗口级），只在主窗口获得焦点时触发；切到其他程序就全部失效。
- Linux 上设计依赖合成器 keybind（niri/hyprland bind → CLI → IPC），Windows 没有对应机制，也没有任何系统级热键注册。

### 新增：可自定义全局呼出快捷键
- `app/ui/global_hotkey.py`（新）：Win32 `RegisterHotKey(NULL, id, mods, vk)` + `QAbstractNativeEventFilter` 捕获 `WM_HOTKEY`；线程级注册（hwnd=NULL），窗口隐藏/托盘时仍有效。非 Windows 返回 None。
- 坑1：PySide6 `QKeySequence[0]` 返回 `QKeyCombination`，用 `.toCombined()`；修饰符枚举必须用 `.value` 取 int（`int(KeyboardModifier)` 报错）。
- 坑2：管理器类必须继承 `QAbstractNativeEventFilter`（只继承 QObject 时 installNativeEventFilter 报 TypeError）。
- 坑3：配置 schema 新增 `HotkeysConfig.global_summon`，默认 "Ctrl+Alt+A" 在中文用户机器上必被 QQ/微信占用（错误码 1409），改成 "Ctrl+Alt+T"。占用时降级为 warning 不崩溃。
- 设置 → 外观与快捷键 加 `QKeySequenceEdit`（在 QtWidgets 不是 QtGui！）行「全局呼出快捷键」，PortableText 序列化；清空即禁用。
- 主窗口 closeEvent 真退出时 `rebind([])` 反注册（线程级热键不随窗口销毁释放，同进程重复注册会 1409）。

### 顺手修复：Windows 上单实例 IPC 唤起完全失效（test_server_emits_command）
- 根因：Windows 命名管道下 `QLocalSocket.waitForBytesWritten` 恒返回 False 且缓冲区不排空（Qt 已知怪癖），数据只能靠事件循环在 ClosingState 期间刷出；`notify_running` 的局部 socket 函数返回即被 GC，写入被中止 → 服务端永远收不到。Linux 域套接字不受影响。
- 修复：`notify_running` 模块级列表保活 socket + 泵 `processEvents` 直到 UnconnectedState（timeout 封顶），`disconnected` 信号触发 `deleteLater` 清理。
